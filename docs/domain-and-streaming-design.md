# 领域模型与分阶段资源调度设计

状态：2026-09-16 设计基线，待实现与验收。本次仅设计文档，未检查代码。本文细化 `architecture.md` 的领域模型与流式调度；预算数值是可配置的起始参数，不是已测得的性能结论。

配套 [交付接口契约](delivery-contracts.md) 固定时间单位、变换方向、框中心、快照、保存介质与测试接口；[独立验收清单](acceptance-checklist.md) 用于交接后的逐项裁决。

## 1. 设计决定

1. 权威数据围绕轨迹、静态几何、属性、复核组织；稳定业务 ID 与内部存储槽位分离。稀疏关键帧是事实，逐帧解析结果是缓存。
2. 一条领域命令同时产生数据修改、影响范围和缓存失效信息。复核有效性由所依赖的内容决定，不能只看全局 revision。
3. 预取仅产生候选资源需求，不承诺下载、解码或 GPU 驻留。三个阶段独立排队和预算准入。
4. 当前帧呈现、编辑、拾取共享一个帧上下文；晚到资源不能改变已选定的编辑时刻。
5. 资源不足时优先减少预取和显示细节，不能静默改变标注、坐标或传感器时间。

## 2. 权威文档与运行状态

| 对象 | 职责 | 保存与撤销 |
|---|---|---|
| DatasetManifest | 样本时间戳、参考时间轴、资源索引、世界原点、标定与 pose 版本、资源尺寸信息 | 版本化只读输入；校正另立版本 |
| AnnotationDocument | 文档 ID、schema 版本、dataset 引用、revision，拥有轨迹、几何、属性及复核记录 | 持久化；通过命令修改 |
| Track | 一个动态目标的身份、类别、存在区间、稀疏框关键帧、来源 | 持久化；领域聚合根 |
| StaticGeometry | 折线/多边形的稳定 ID、类别、顶点、有效区间、来源 | 持久化；与 Track 平级，不伪装成零速度轨迹 |
| AttributeStore | 按对象、属性键、时间范围及传感器组织属性赋值 | 持久化；与对象修改原子提交 |
| ReviewLedger | 审核记录、覆盖范围、依赖摘要、问题项、候选接受/驳回记录 | 持久化；历史记录不原地改写 |
| SessionState | 工具、选择、悬停、视角、过滤、请求帧与呈现帧 | 不属于标注 undo；偏好可另存 |
| DerivedCache | 当前帧状态、空间索引、投影、渲染实例、资源副本 | 不进入文档快照，可重建 |

业务对象使用持久化 UUID；内部可用 `u32 slot + generation` 加速访问，但两者之间必须有映射。删除后重建不能复用旧业务身份；undo 删除恢复原 ID。实例槽位压缩或缓存驱逐不能改变对象 ID。

坐标和变换在权威模型中使用 Float64 精度；JS number 符合此要求。渲染以当前局部原点为基准转 Float32。局部原点改变只重建派生数据，不写回标注。持久化记录原点、单位、轴向和变换方向。

领域边界不要求“每对象一个类”。现有 typed-array 存储可保留，前提是 TrackRepository/GeometryRepository 暴露领域读写契约，不让组件列和 GPU 布局成为公共 API。

## 3. 时间、轨迹与几何规则

### 3.1 时间区间

内部统一用半开区间 `[start, endExclusive)`，包含 start，不包含 endExclusive。UI 对用户显示首末帧；导入既有闭区间 `[s,e]` 时转换为 `[s,e+1)`，格式版本与导出转换必须明确。单帧属性的区间为 `[f,f+1)`。

帧号用于索引和用户操作；插值比例、速度使用参考时间轴的采样时间戳。各相机与点云样本具有各自时间戳，通过 manifest 指定的匹配规则关联参考帧。首版必须显式声明同步容差，超出容差视为缺失，禁止无提示地选取任意最近样本。

参考时间轴必须有限且严格递增，导入时拒绝重复或倒序时间；原始传感器乱序由接入层按样本 ID 建索引，不能用排序后的数组位置冒充稳定样本身份。

### 3.2 Track 不变量

- 首版一条 Track 有一个连续存在区间。遮挡不终止存在；离开标注范围后再次出现，建立新 Track，可用 `relatedTrackId` 记录人工关联。多段存在区间留待实际数据要求时扩展。
- 每条已提交 Track 至少有一个关键帧，帧号唯一、递增且位于存在区间内；框尺寸为有限正数，位置和 yaw 必须有限。
- 区间内首关键帧之前和末关键帧之后采用最近关键帧 hold；区间外返回 absent，不能自动外推。
- 默认位置与尺寸线性插值，yaw 走最短弧；恰为 π 的差值统一选正方向。hold 策略取左侧关键帧。策略属于 Track 配置。
- 类别和来源属于 Track 元数据；速度由时间戳差分得到，人工覆盖速度作为独立时间属性，不反向改变轨迹位置。
- 对象状态包含来源 human/model/imported 与候选状态。接受模型候选并不等于完成复核。

### 3.3 编辑与结构操作

普通移动、旋转、尺寸编辑默认仅设置当前帧关键帧：已有则替换，没有则基于当前解析值新增。时间轴在预览时显示受影响区间。修改整个 Track 或某个区间必须显式选用对应命令，不能由拖动隐式推断。

影响范围以修改前后两组关键帧依赖区间的并集计算。新增、删除或移动关键帧都要考虑左右邻接区间和首末端 hold 区间，不能仅标记编辑的那一帧；允许保守扩大，禁止遗漏。属性修改按属性赋值区间计算影响。

首版规则：

| 操作 | 精确定义 |
|---|---|
| 删除关键帧 | 删除后重新插值；最后一个关键帧不得直接删除，用户可删除整条 Track |
| 拆分于 f | 原 ID 保留 `[s,f)`；新 ID 获得 `[f,e)`；两侧必须非空；以拆分前解析值补齐左端 f−1、右端 f 的边界关键帧，保留原曲线，按区间分割属性 |
| 合并 | 用户明确选择保留 ID；首版只接受同类别、时间相邻且不重叠的 Track；元数据冲突需显式给定结果，否则整笔拒绝；以边界解析值补关键帧防止形状意外变化 |
| 裁剪 | 保留范围必须非空；写入新首末帧的原解析值，再裁掉外部关键帧和属性，保证保留帧不因裁剪而变化 |
| 延伸 | 扩大存在区间，新区间默认使用边界状态 hold；新范围未复核，用户可再插入关键帧 |
| 整体变换 | 对选定 Track 的全部关键帧变换；不修改世界原点、pose 或静态地图；整条存在区间复核失效 |
| 区间变换 | 先捕获原解析结果并在区间内首末帧、相邻外侧帧补边界关键帧，再变换区间内状态，保证范围外帧不变；单步撤销所有补点与变换 |

首版多边形为简单外环，不支持孔洞；至少三个不同顶点、禁止自交，提交时校验。折线至少两个不同顶点。静态几何顶点编辑作用于其整个有效区间；局部时间形变需要显式拆成两个几何对象，不能隐式创建动态多边形。

高度采样返回 `ready(value, source, resolution) / loading / missing / error`。创建预览可以等待高度；提交必须使用有效采样值、人工输入值或用户明确选取的零平面，并记录来源。不得将低精度 LOD 高度无提示地当成精确高度；采样分辨率需要达到数据集声明的标注容差。

## 4. 属性模型

schema 定义 `key/type/default/allowedScopes/enum/range/required`。首版属性时间行为统一为显式区间覆盖，不做数值插值或隐式无限向后继承；需要持续覆盖时直接设置区间。几何插值与属性作用时间独立。

赋值记录包含 `objectId, key, optional sensorId, optional interval, value`；无 interval 表示对象全有效期。schema default 未给值时返回 unknown，不能冒充人工已填值。

每个属性由 schema 声明 object 或 sensor 作用域。object 属性的解析优先级为时间覆盖 → 对象基础值 → schema default；sensor 属性在指定传感器内采用同样优先级，无传感器上下文返回 unknown，不把另一相机值回退进来。颜色、子类使用 object；occlusion/truncation 使用 sensor；moving 使用 object 时间覆盖。

同一对象、键、传感器的时间覆盖保持不重叠：设置 `[a,b)` 时分裂或替换旧区间，合并相邻相同值。清除覆盖恢复基础值或 default。改类别时一次提交同时检查属性兼容性；不兼容值须在预览中列出并随命令明确清理，不能悄悄忽略。

已有“关键帧携带逐帧属性”导入为单帧区间；若旧格式实际表示向后 hold，必须由迁移器按旧语义展开区间，禁止猜测。属性独立存储后，删除几何关键帧不会顺便删除该帧的人工属性。

## 5. 复核、影响范围与事务

### 5.1 复核覆盖

复核分两个维度：对象检查（几何、类别、属性）和场景完整性检查（漏标、重复标、身份关联）。只有对象都通过不能证明没有漏标，因此序列交付必须同时满足这两个维度。

ReviewRecord 保存审核人、时间、对象/场景范围、帧区间、传感器范围、检查维度、结论、问题项、当时文档 revision 与依赖摘要。摘要覆盖被检查的内容及 schema/dataset/calibration/pose 版本；revision 供审计，不作为唯一有效性判断。

有效状态为 `unreviewed / passed / rejected / stale`。记录保持不可变，当前覆盖由记录与内容依赖计算；修改后历史 passed 仍保留，但受影响范围显示 stale。区间分段保存，避免一个局部修改使整个序列重新审核。

失效规则：

- 几何或运动修改：影响区间内该对象几何检查及场景完整性检查过期。
- 类别或存在区间修改、创建、删除、拆分、合并：相关对象检查和对应场景完整性检查过期；拆分/合并的身份检查必须重做。
- 属性修改：对应对象、传感器和时间范围的属性检查过期；无需使无关相机几何复核失效。
- 静态顶点修改：该几何整个有效区间的相关检查过期。
- 标定/pose/schema 版本变化：所有依赖该版本的覆盖过期；缓存同时失效。

undo 若精确恢复被审核的内容及所有依赖版本，可重新匹配原审核记录；若依赖已变，不能仅靠 undo 把 stale 改回 passed。对象删除的反向恢复保留其原 ID，审核记录不随对象删除而销毁。

交付条件：目标区间所需对象检查与场景完整性检查均通过、无未解决阻断问题、必填属性/schema 校验通过、无未处理候选、目标导出可读取。标注量、复核覆盖率、数据完整度单独报告。

### 5.2 命令提交

命令输入包括稳定对象 ID、基准 revision 和明确作用范围；冲突时拒绝并重新预览。输出为 `ChangeSet`：领域补丁、逆补丁、受影响对象/区间/维度，以及 dirty hints。dirty hints 可重建，不是持久化事实。

一次手势执行 `begin → preview* → validate → commit/cancel`。开始时锁定呈现帧上下文；预览属于 Session；切帧先取消未提交手势；松手一次提交；Esc/pointercancel 取消。提交期间暂不接受下一笔依赖编辑；保存失败保留可见预览以便重试或取消，不显示“已保存”。

单写者提交顺序：校验并暂存领域结果 → 持久化补丁/逆补丁与 revision 的原子事务 → 发布权威文档变更及复核重算 → 显示已保存。提交后、发布前崩溃可通过日志重放恢复；提交前崩溃丢失的仅是尚未确认保存的预览。undo/redo 本身也作为日志事务持久化。

## 6. 三阶段资源体系

### 6.1 资源身份与表示

ResourceKey 包含 datasetVersion、资源类型、传感器/帧/瓦片/节点标识、LOD 和内容版本；表示版本另含 decode format。投影派生缓存还必须包含标定、pose、文档版本和局部原点。request epoch 属于需求订阅，不属于不可变资源身份，以便多个请求共享一次下载。

每种资源可以同时拥有三个表示：encoded（下载字节）、decoded（CPU 数据/解码图像）、gpu（buffer/texture）。不能用一个线性状态表示它们：释放 GPU 后仍可保留 decoded，释放 decoded 后可保留 encoded。每种表示独立记录 absent/queued/inFlight/ready/failed、占用、预约和引用者。

Provider 覆盖 PointCloudFrames、CameraFrames、BevPyramid、HeightField、PotreeOverlay，负责描述体积、执行 fetch/decode/upload 和释放表示。预算和优先级属于统一 ResourceCoordinator，不能由各 Provider 自行绕过。

### 6.2 初始预算

采用显式资源配置，不依据不可靠的浏览器显存探测自动承诺容量。默认 standard 配置如下，所有数值均以 MiB 为单位：

| 账本 | 上限 | 包含内容 |
|---|---:|---|
| encoded | 192 | 缓存字节及下载中已预约字节；网络响应复制计入临时账本 |
| decoded | 640 | 点云数组、图像解码表面、高度列、派生 CPU buffers、正在解码的目标输出预约 |
| transient | 192 | 解码器 scratch、输入复制、上传 staging、操作中的额外峰值预约 |
| CPU 资源总额 | 1024 | 前三项占用与预约之和；转移所有权不重复计，复制必须计两份 |
| GPU 估计总额 | 512 | buffers、纹理、mipmap、渲染目标、文字图集、上传中的预约及余量 |
| GPU 驱动余量 | 96 | 从 512 中保留不可分配；应用可记账的驻留与预约最多 416 |

这些是受管理资源预算，不等于整个浏览器进程 RSS 上限。JS 领域数据、日志索引、浏览器内部缓存与驱动隐藏开销单独监测；超过实测目标硬件能力时降低配置。文字、标注实例和渲染目标同样记 GPU 账，不能只统计瓦片。

高水位为各可分配预算的 85%，低水位为 70%。高水位以上停止低优先级准入并驱逐可回收资源到低水位；当前帧资源可在硬上限内继续准入。硬上限按 `resident + reserved + newPeak <= limit` 检查，准入前先预约，成功后转换预约为实际占用，失败/取消必须释放预约。

体积估算：点云依据 header 的点数/字段与目标布局；图像依据尺寸、解码格式与 mipmap；有 mipmap 的 RGBA8 纹理约为 `w*h*4*4/3`，另加 staging。未知体积先取小范围 header 或 manifest 描述；服务器不支持 Range 时采用有硬接收上限的流式读取，超过上限终止。不能先完整下载/解码再发现超预算。

无法提供峰值估算的解码器必须在独立 Worker 中受输出规模限制运行；若 scratch 峰值没有可信上界，该 Provider 不通过 standard 配置验收，需补测并建立保守预算，不能声称全局硬内存保证。

### 6.3 队列与顺序

| 阶段 | 初始限制 | 调度规则 |
|---|---|---|
| Fetch | 总并发 6；推测预取最多占 4 | 保留 2 个位置给当前呈现和最新请求帧；无关键请求时允许临时借用，有请求时停止补充低优先级工作 |
| Decode | 2 个 Worker；推测解码最多占 1 | 当前/目标帧优先；输入、输出和 scratch 一起预约；大任务支持分块或取消，不能抢占则等待并显示 loading |
| Upload | 一个主线程上传队列 | 每次 rAF 启动上传的预算目标为 2ms 且最多 8MiB；允许分块的 buffer 分块上传，未完成不发布 |

上传时间是测量反馈目标，不能中断已开始的同步 WebGL 调用。单张纹理大于 8MiB 时，保证驻留准入后独占一次上传批次并记录耗时；若持续超出交互预算，数据接入阶段生成瓦片/显示用降采样版本，不能通过“每帧限制”掩盖长任务。

优先级依次为：P0 当前帧缺失的必要资源与编辑所需高度；P1 最新目标帧必要资源及截止时间最近的播放帧；P2 当前视口细化；P3 方向性预取。相同级别按呈现截止时间、可见收益、估计成本排序；P2/P3 可老化提升，但不得超越 P0/P1。

暂停稳定时才大量细化；播放中限制静态 Potree/BEV 细化占用。实际调度以样本呈现截止时间为准，不只按帧距离；切换方向会立即重算优先级。

### 6.4 预取与驻留

- **候选范围**：最大 ±45 帧，只代表可以考虑的需求。暂停时当前帧两侧各 2 帧为初始候选；高速拖轴时只保留最新目标帧，停止推测解码。
- **下载前视长度**：`ceil(effectiveFps * (p95 fetch+decode+upload latency + 0.3s))`，以 2–45 帧截断；沿播放方向优先。未知耗时时从 5 帧起步；反方向保留最多 2 帧候选。
- **CPU 解码**：初始当前帧 + 前向 3 帧 + 后向 1 帧是上限目标；在最多 12 帧范围内按实测截止时间和剩余预算扩展。总延迟要求超过可驻留能力时缓冲/降速，不能突破预算。
- **GPU**：当前可见帧组和一个准备中的目标帧组；不把整条预取窗口上传。相机只准备当前布局显示的视图，隐藏视图不要求 GPU 驻留。
- **缓存保留**：由字节预算决定，LRU 仅用于同优先级且未被 pin 的候选；淘汰顺序先远期推测，再不可见高 LOD，再非必需邻帧。点云在主视图与三视图共享 GPU buffers，最后一个引用释放才 dispose。

例如每帧 100 万点、16 字节/点，91 帧需要约 1.36 GiB 解码数据，已超过默认 CPU 总预算；默认初始 5 帧约 76.3 MiB，仅为点云数组。多相机、临时副本和纹理必须另外计入，因此帧数目标永远服从字节准入。

### 6.5 压力、取消与失败

资源需求使用 lease/refcount；呈现中的资源、活跃手势所依赖的资源被 pin，不能被 LRU 释放。每次切帧先预约旧帧与目标帧共存的峰值；目标必要资源准备完成后，渲染边界原子切换 lease，再释放旧帧引用。

共存无法满足时：先取消推测工作并回收非必要资源；仍不足则取消编辑预览，明确显示 loading 并关闭旧帧拾取，释放旧帧组后加载目标。单帧工作集仍超过预算时给出可行动错误，使用已经声明的显示 LOD 或提高配置；禁止无限驱逐重试。视觉 LOD 不改变权威标注和用于精确采样的数据。

取消需求不一定取消底层下载：只有无其他 lease 的请求才 abort。不能中断的解码完成后检查 lease 和 epoch；无需求则释放结果，仍被需要则入缓存，但只有有效呈现上下文可采用它。已 abort 任务不立刻释放仍被 Worker 使用的内存预约，须等确认终止或结果释放。

超时/临时网络错误至多自动重试 2 次，退避带抖动；404、格式不支持、非法 header 直接记录错误，等待用户重试或数据版本变化。错误必须按资源身份缓存，避免每次渲染重发请求。

WebGL context lost 时 GPU 表示全部失效，暂停播放与编辑，保留权威文档和可用 CPU 表示；恢复后优先重建当前帧。CPU 中需要重新上传的 typed arrays 在真实释放前都计入 decoded，不能只执行上传就假定内存已释放。

## 7. 帧协调与可观测性

FrameCoordinator 分开 requestedFrame 与 presentedFrame。FrameContext 包含 referenceTime、各传感器 sampleId/time、dataset/calibration/pose 版本、annotation revision 与 request epoch。ready 是“该视图所需的资源及投影已准备”的状态，不是 fetch 完成。

点云模式必需当前点云；BEV 模式必需已配准的底图兜底；可见相机缺失可标记 unavailable，该视图清空旧图像/旧投影并关闭拾取，不阻断其他合规视图。提交需要高度时，高度是该手势的额外必要资源。

复核播放默认逐采样帧呈现，资源不足即缓冲并报告实际播放速率。4x 是目标速度，不承诺任意硬件/数据下可逐帧达到；需要允许跳帧时只能显式进入快速浏览模式，并标示未呈现区间，不能自动记为已复核。

只读诊断接口输出：呈现与请求上下文、每阶段驻留/预约字节、队列长度、各优先级等待时间、缓存命中、取消/晚到次数、上传耗时、预算拒绝原因、lease/pin 数、当前文档/保存 revision、手势状态和复核覆盖。用户界面显示“等待下载/解码/显存空间”这类可解释原因，详细计数放诊断面板。

## 8. 实施顺序与验收

| 阶段 | 交付边界 | 必须通过的证据 |
|---|---|---|
| D1 | 稳定 ID、时间区间、Track/Geometry/Attribute 契约与格式迁移 | 插值帧编辑、拆分/裁剪前后保留帧等价、属性区间覆盖、保存往返一致 |
| D2 | ChangeSet、手势事务、复核依赖与持久化 | 一次拖拽一次 undo；Esc 无修改；插值影响范围复核过期；undo 恢复内容后正确匹配原审核；提交前后崩溃一致 |
| S1 | 资源多表示账本、lease、预算预约与错误模型 | 假 Provider 制造峰值、乱序、取消和双视图引用；每步账本无超额/负数/提前释放 |
| S2 | fetch/decode/upload 三队列与 FrameCoordinator | 实际 Worker/浏览器验证慢解码、旧请求晚到、拖轴、单帧过大和共存不足；无旧帧误编辑 |
| S3 | 真实短序列闭环与规模验收 | 1000 Track × 3000 帧，声明关键帧密度、点数、相机分辨率和硬件；30 分钟往返操作无资源持续增长；记录 p95/p99 |

测量输入到一致帧呈现、输入到预览、undo 到呈现、保存提交完成四个独立延迟。缓存已就绪的切帧 p95 <100ms、小编辑 undo/redo 到呈现 p95 <50ms、拖拽预览 p95 ≤50ms 为目标；持久化和大事务单独报告。10fps 以实际采样帧呈现统计，不能用 rAF 次数替代。

浏览器验收必须发真实鼠标/键盘事件并读取只读状态断言，不能绕过 UI 调用领域命令代替画框。合成数据给独立数学答案，真实数据验证传感器语义，故障注入验证失败路径；完成状态按证据更新，不能因设计写完而打勾。
