# 交给实施 AI 的任务书

状态：可交接的任务定义，尚未执行。当前作者只检查了文档；历史功能清单不是经过核验的代码事实。

## 1. 任务与边界

第一轮 M1：实现并证明真实序列加载 → 画轨迹 → 插值帧修改 → 跨视图检查 → 撤销 → 保存恢复 → 复核 → 自有 JSON 导出；同时交付自动化与证据，使另一位 AI 能独立重跑。

开始前阅读 `docs/README.md` 所列规范与仓库实际 AGENTS.md。用户将本任务交给实施 AI 后，实施范围包括读取/修改代码、编写必要测试和运行浏览器；此前设计者“未看代码”的范围说明不限制未来受委托的实施任务。

不要求推倒已有实现。先查差距，保持已有可用功能，以小块可验证修改满足领域与资源契约。首版不是多人协同、所有投影模型或所有导出格式的全面重构；额外需求继续列入矩阵，不得删掉来制造通过。

## 2. 开始时必须产出的差距表

记录当前工作区基线、既有未提交修改、依赖和实际运行方式。对验收清单每个 ID 标记：已有且待验证 / 需修改 / 缺外部输入 / 本轮范围外。引用真实文件与检查结果，不能复制历史“已实现”声明。

检查 R-mini 是否具备数据、标定、时间、BEV 配准与参考答案；缺失时明确报告准确缺项，继续合成夹具、核心实现及测试设施。不得编造真实数据、预期答案、测试结果或性能数字。

规范冲突与未定义输入写入 `DECISIONS` 部分；可以自主选择常规内部实现，不能静默改变业务语义、坐标、数据格式、测试容差或门槛。确有必要修订规范时说明动机、影响、兼容性及验收变化，独立列出供验收者核对。

## 3. 按交付包推进

| 包 | 工作与依赖 | 交付给验收者的内容 |
|---|---|---|
| H0 基线与数据 | 差距表、S/R 夹具清单、schema/非法样例、独立答案 | 可重现启动说明，数据校验和，缺项报告 |
| H1 领域与事务 | 稳定 ID、时间/坐标、关键帧编辑、属性、持久化、undo | 领域测试、迁移样例、事务失败/恢复证据 |
| H2 帧与资源 | 三阶段预算、Worker、lease/pin、FrameCoordinator | 乱序/低预算测试与资源日志 |
| H3 用户闭环 | UI 精确编辑、跨视图、复核、导出、只读观测 | J01 自动化、独立导出校验、原始证据 |
| H4 可靠性与交接 | F01–F06、浏览器恢复、可重现命令、报告 | 完整验收包与未通过项；不得声称已通过独立验收 |

H1/H2 的最小能力应尽早接入 H3，不等所有静态工具和所有相机模型完成才跑 J01。每次修复保留原失败证据，重跑相关用例并在阶段结束跑完整旅程。

## 4. 必须交付的文件与证据

- `DELIVERY.md`：完成范围、变更摘要、与设计偏差、实际可运行命令、测试数据位置、已知问题、下一轮未覆盖能力。
- 版本化 manifest/snapshot schema、合法与非法样例、旧格式迁移说明。
- 独立标准答案与导出读取器；说明何处未引用产品实现。
- `docs/acceptance-checklist.md` 各项对应的实现位置、测试 ID、run-id 与结果映射。不能将实施自测结果填成独立验收通过。
- 原始运行目录：report、环境、动作、trace/截图、观测值、导出文件、性能数据；与代码构建和夹具 hash 关联。
- 自测中所有失败、重试、BLOCKED、FLAKY；不能只保留最后一次成功。

有 Git 时给出提交/差异基线；未提交交付另提供源码差异摘要或文件校验和，保证证据能定位实际内容。运行环境变更与依赖安装说明写清楚，不能要求验收者猜测本地服务状态。

禁止用以下方式达成表面通过：跳过失败用例；直接调用业务 API 替代 UI 操作；在测试模式走另一套业务管线；将实际输出重新生成 expected；放宽容差或更新视觉基线不说明理由；用刷新替代崩溃；将同源往返测试当成唯一正确性证明。

## 6. 可直接发送给其他 AI 的任务提示

> 在此仓库实施 M1 标注闭环。先阅读 docs/README.md、docs/implementation-handoff.md 和其中引用的规范，检查实际代码并建立差距表。按领域、资源、接口和验收契约完成实现，不改低验收标准。交付真实 UI 驱动的 J01、F01–F06、独立导出验证器、可重现命令及原始证据，最后提交 DELIVERY.md。真实数据或参考缺失时准确报告并继续其他工作；不要伪造通过，不把实现自测宣称为独立验收。验收者随后会根据 docs/acceptance-checklist.md 独立运行。
