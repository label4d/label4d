# AI 自主交互验收协议

状态：设计，尚未实现测试设施或运行验收。目标是验证“真实序列加载 → 画轨迹 → 插值帧修改 → 跨视图检查 → 撤销 → 保存恢复 → 复核 → 导出”。本轮仍只读写文档，不检查实现代码。

其他 AI 的实施交接见 [任务书](implementation-handoff.md)，数据/观测/命令定义见 [接口契约](delivery-contracts.md)，验收顺序和逐项 ID 见 [验收清单](acceptance-checklist.md)。这些文件引用的 verify 命令均为待实施接口，不代表当前已可运行。

## 1. 工具分工

主干采用 AI 当前可用的浏览器交互工具，例如 browser use、computer use、浏览器 MCP、Playwright 或具备等价能力的工具，通过真实鼠标、键盘、文件选择、下载完成固定旅程。能够使用语义定位时优先用于 DOM 面板，Three.js 画布使用可验证的指针坐标或等价交互方式；稳定复现的问题沉淀为可重复执行的回归用例。

独立验证器检查文档、帧身份、复核覆盖和导出结果。AI 组织执行、分析失败和提出修复，但不以“看起来对”替代机器断言。浏览器交互工具可以不同，只要能够执行真实用户操作、读取必要反馈并留下可核验的动作与结果证据。

首条闭环不必全靠 computer use，也不应只靠单元测试。采用三份证据：真实输入可达、数据语义正确、画面反馈一致。

## 2. 先准备四样东西

1. **S-mini 合成夹具**：至少 31 帧、明确时间戳、确定 BEV 配准与相机标定，已知轨迹和投影控制点。预期值由手算/独立数学实现给出，不调用产品 resolve/project 生成标准答案。
2. **R-mini 真实夹具**：20–60 秒连续真实采集数据，至少包含点云、相机、pose/标定和有配准关系的 BEV 底图，选定可跟踪目标及核验帧。资产清单含版本与校验和，使用生产加载器。若某模态缺失，相关路径为未验证，不能用合成资源替代后仍声称真实全链路通过。
3. **只读观测接口**：测试构建提供当前文档摘要、关键帧/属性、presented/requested context、selection、history、saved revision、review coverage、各阶段资源账本。返回不可变副本，禁止用接口添加对象、切帧、提交复核或改变历史。
4. **外部断言与证据包**：UI 驱动和预期答案分离；从下载文件用独立读取器解析。每一步记录输入、截图、观测值、断言与耗时。

数据准备、固定视口大小和受控故障配置可以由测试夹具完成；业务操作必须经用户界面。资产不存在时报告 BLOCKED 并继续可完成的合成验证，不能把缺输入归因于产品失败。

真实夹具的流程正确性可以自动判定；其几何标注质量需要已核验参考或明确容差。没有参考时，AI 能报告可疑对齐问题，不能自行宣称达到生产标注精度。

## 3. 画布如何自动操作

- 工具栏、帧输入、对象列表、属性编辑器、保存状态、审核与导出使用可访问名称和稳定定位标识；这也是用户可用性的一部分。
- 固定主夹具的 BEV 视角、视口尺寸与 devicePixelRatio；脚本先读取 canvas 的实际边界，再按夹具定义的归一化位置发 pointerdown/move/up，不能把整屏绝对坐标写死。
- 夹具提供世界点与预期投影位置。通过独立变换计算主场景操作点，不向产品询问“点哪里就一定选中”；产品投影接口可以用于诊断，不能成为唯一正确性来源。
- 3D 复杂目标首次由 computer use 按画面定位与操作；固定视角后将可重现输入转为脚本。其他视角/窗口尺寸另设变体，不能只验证一个布局。
- 多步拖动后核对实际位移、关键帧和历史；相机点击后核对同一对象 ID，再检查高亮截图。数据正确而高亮不见，仍然失败。
- 等待 frame presented、保存完成或指定状态条件，并设置超时；不靠固定 sleep 或 networkidle，流式页面可能持续联网。
- 应用报告 render revision 只表示应用发出了对应渲染，不独立证明像素正确；仍需截图/像素控制点检查。性能测试把 GPU 提交与可观测呈现的测量限制写清楚。

## 4. 第一条端到端旅程 J01

主旅程在 S-mini、R-mini 各跑一次，各自报告结果。S-mini 在均匀 10Hz 时间轴上，第 10 帧位置 `(0,0,1)`，第 20 帧 `(10,0,1)`，尺寸 `(4,2,2)`、yaw=0；由 BEV 画框创建，再经用户可见的精确输入设置基准位置。帧 15 原位置应为 `(5,0,1)`。R-mini 使用其真实参考点，不套用合成坐标。

| 步骤 | AI 通过 UI 做什么 | 独立断言与证据 |
|---|---|---|
| J01-1 加载 | 选择真实/合成 manifest，等待目标帧可编辑 | 数据集校验和匹配；时间戳和传感器 ID 正确；图像、点云、投影同属有效上下文；截图可见必要数据 |
| J01-2 画轨迹 | 到第 10 帧画框，到第 20 帧为同一对象设关键帧；明确存在区间覆盖 10–20 | 恰为一个稳定对象；关键帧为 10、20；尺寸正值；取消一次额外绘制不会增加对象；保存基线 B0 |
| J01-3 修改插值帧 | 到第 15 帧确认是插值态，拖动目标，然后用精确输入将位置设为 `(5,2,1)` | 新增 15 帧关键帧；10/20 不变；合成帧 12 为 `(2,0.8,1)`、18 为 `(8,0.8,1)`；拖动与精确输入分别是各自一条命令，记录历史差值 |
| J01-4 跨视图 | 在相机图像选择目标，切回 BEV/3D 检查 | selection 始终同一 ID；没有副本；各视图可见高亮；独立投影控制点误差达标；底图与标注时间一致 |
| J01-5 撤销 | 逐次撤销本次精确输入和拖动，再按相反次序重做 | 撤销精确输入回到拖动结果；再撤销拖动回到 B0 且 15 帧关键帧消失；重做恢复两笔操作后的语义状态；Esc 取消的预览不在历史中 |
| J01-6 保存恢复 | 等待已保存，关闭并重启浏览器，用同一磁盘 profile 重开项目 | 不重新导入内存状态；稳定 ID、关键帧、属性与保存前等价；saved revision 与文档对应；UI 可再次拾取和编辑 |
| J01-7 复核 | 检查目标区间，提交对象检查与场景完整性检查；再改 15 帧，检查失效，恢复/重新审核 | 审核范围与依赖记录正确；相关范围 stale，未受影响范围不被全局 revision 无谓清空；存在 stale 时正式交付被阻止 |
| J01-8 导出 | 完成所需复核，通过 UI 下载自有格式与已指定目标格式 | 独立读取器解析成功；对象、时间、坐标、属性映射正确；自有格式在另一空白文档导入后语义等价；下载成功不等于导出正确 |

语义等价比较规范化业务内容，不比较 JSON 键顺序、内存槽位或所有操作时间戳；稳定 ID、关键帧、属性和作用区间必须相同，浮点容差提前固定。重做/撤销后的文档 revision 可以增加，不要求回退；审核有效性单独断言。

首轮 J01-8 必须验收自有 JSON。nuScenes 必须先确定具体导出 profile 与下游读取器，再验其坐标/类别/时间映射；未确定时该分项标记 BLOCKED，不得泛称 nuScenes 兼容通过。草稿备份允许含未复核内容，正式交付导出才受复核门禁约束。

## 5. 必须跟随主旅程的故障变体

| ID | 注入与操作 | 通过条件 |
|---|---|---|
| F01 乱序 | 故意延迟旧帧图像，再快速拖到新帧 | 旧响应不能覆盖新帧，不能通过旧画面拾取或提交新帧标注 |
| F02 取消 | 拖到画布外、Esc、pointercancel、切帧 | 按约定取消；文档/历史不变；预览和指针捕获释放 |
| F03 保存失败 | 存储适配器注入配额/事务错误 | 不显示已保存，不发布半笔权威修改；可取消/重试；重开为最后确认版本 |
| F04 异常终止 | 在事务提交前后、undo 保存后终止隔离测试浏览器进程 | 恢复一致；已保存内容保留，撤销对象不复活；保留磁盘 profile，不用 storageState 冒充恢复 |
| F05 低预算 | 缩小 encoded/decoded/GPU 各预算并往返切帧 | 无账本超额、错误释放或无限抖动；必要时明确 loading；旧视图关闭编辑；UI 仍响应 |
| F06 审核过期 | 修改关键帧、单相机属性或标定版本 | 按影响区间/维度失效；正式交付阻止，草稿仍可备份 |

测试故障开关只影响网络、时钟、存储适配器或资源容量，不提供“直接把业务状态设成通过”的捷径。正常关闭、刷新与进程异常终止分别报告；进程终止测试也不能证明机器断电级持久性。

## 6. AI 执行与修复循环

1. 读取已冻结的任务规格、夹具和独立预期，检查服务/资产/测试浏览器就绪。
2. 执行固定 UI 旅程，按检查点保存证据；失败保留原运行，不通过修改 expected 或视觉基线消除红灯。
3. 将失败归为产品缺陷、测试设施缺陷、缺少外部输入、视觉待复核；AI 可以分析，不能自动把不确定变成 PASS。
4. 若当前任务授权实现修复，修产品或测试设施后重跑失败用例及受影响回归；本轮只设计，未授权启动代码实现。
5. 对画布行为和可发现性，用 computer use 独立跑一次相同任务：只给用户目标，不给组件内部方法或标准点击坐标，记录误点、卡住和理解偏差。
6. 固定套件通过后，再用记录种子的随机动作探索切帧、取消、过滤、窗口 resize 与 undo 组合；检验不变量，保存最短复现序列。

computer use 发现的问题需可复现；单次视觉判断不能自动更新 golden。修复后的同一失败至少重跑，并做一次完整 J01；重试后通过但首次失败的情况标记 flaky，不能静默算稳定通过。

## 7. 产物和门槛

每次运行建立独立目录，至少包含：

```text
artifacts/<run-id>/
  report.json          # 用例状态、断言、失败分类、证据路径
  environment.json     # 构建版本、浏览器、OS、GPU、DPR、视口、数据校验和
  actions.jsonl        # 输入顺序、定位/坐标、条件等待、随机种子
  observations.jsonl   # 帧上下文、文档与保存版本、选择/历史/复核、资源账本
  trace.*              # 所用浏览器工具能够提供的 trace、动作日志或会话记录
  screenshots/         # 关键步骤及所有失败点
  exports/             # 原始下载文件及独立校验结果
  metrics.json         # 延迟、帧呈现、资源峰值、重试与错误
```

最终状态为 PASS、FAIL、BLOCKED、NEEDS_REVIEW、FLAKY，不能只有成功/失败。报告必须区分 S-mini 与 R-mini、固定自动化与 computer use、流程正确性与标注几何质量。

第一阶段完成定义：J01 在 S-mini 和 R-mini 上各连续三次完整通过，F01–F06 有独立证据，computer use 无未解决的阻断操作问题。连续三次用于基本重复性检查，不构成统计可靠性保证；此阶段也不代表规模性能或所有功能已验收。

下一步实施顺序：准备/确认真实夹具 → 增加只读观测与稳定 UI 定位 → 实现一个完整 J01 → 补独立导出验证器 → 补 F01–F06 → computer use 探索 → 性能与长时测试。不要先铺大量截图快照而没有一条可恢复、可导出的完整旅程。
